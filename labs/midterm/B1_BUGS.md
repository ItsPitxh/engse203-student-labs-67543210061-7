| คอลัมน์ | ใส่อะไร | ตัวอย่างสิ่งที่เขียน *(บั๊กสมมติ)* |

| **ไฟล์ : บรรทัด** | ไฟล์ที่แก้ + เลขบรรทัด | `Foo.jsx : 12` |

## บันทึกของฉัน — กรอกทั้ง 6 บั๊ก

| # | อาการ (ให้มาแล้ว) | ไฟล์ : บรรทัด | สาเหตุ (ทำไมผิด) | แก้อย่างไร |
|---|---|---|---|---|
| 1 | Console เตือนสีเหลืองเรื่องรายการ (list) ที่แผงสรุป | `SummaryPanel.jsx : 13` | <Article /> ไม่มี prop key ทำให้ map() ไม่สามาถรู้ว่าตัวไหนเป็นตัวไหนเหมือน ID | เพ่ิม prop `key` ลงไป โดยใช้ key ที่ประกาศจาก `map()` ให้มันสามารถเรียง `key` ถูกได้ |
| 2 | ตัวเลข "เสร็จสิ้น" ในแผงสรุปไม่ตรงกับที่เห็นจริง | `DashboardPage.jsx : 51` | `useMemo()` เป็น hook ที่จะทำการเปลี่ยนค่าระหว่างการ render ของ component โดยไม่ต้องคำนวณซ้ำตลอดเวลา แต่จะเปลี่ยนค่าเมื่อมีการเปลี่ยนของ Dependency ถ้าไม่มีการเปลี่ยนก็จะใช้เป็นค่าเดิมของ Dependency นั้นๆ แต่ในโค๊ดไมีมีการระบุ dependency จึงไม่มีค่าเดิมให้คืนทำให้แสดงค่าออกมาเป็น `0` ทุกช่อง | ประกาศ Dependency ด้วย `Requests` |
| 3 | กดตัวกรองสถานะใด ๆ แล้วผลไม่เปลี่ยน (เหมือนกรองไม่ทำงาน) | `DashboardPage.jsx : 55` | มีการเทียบ `Request.status === 'pending'` อยู่ตลอดเวลาทำให้ filter ออกมาแค่ pending | นำ state `statusFilter` มาใส่แทนเพื่อให้ค่าเปลี่ยนตามค่าที่ส่งมาตาม event ของปุ่ม |
| 4 | เปลี่ยน URL `REQ-101` → `REQ-102` แล้วข้อมูลไม่เปลี่ยน | `RequestDetailPage.jsx : 8, 43` | หน้านี้จะมีการเก็บข้อมูลการแสดงผลไว้ใน state `request` โดยจะเช็คว่าถ้าหากมีการโหลดใหม่ก็จะดึงค่า `requestID` มาจาก `useParam()` และถ้าโหลดเสร็จแล้วก็จะเก็บค่าลงใน `request` และเปลี่ยน `loadState('success')` ซึ่งภายใน `useEffect()` ที่จะใช้ดักจับการโหลดของหน้าจอ มีการเขียนดักไว้เป็น `if (ignore) return` ดังนั้นโค๊ดเดิมจึงข้ามขั้นตอนเหล่านี้ไป แต่ยังเก็บ `requestID` แรกไว้ใน `request` อยู่ และพอมีการเปลี่ยนหน้าไม่มีมีการเปลี่ยน state ด้วยทำให้ยังคงแสดง request เดิมที่ค้างอยู่ใน `request` อยู่ และก็ไม่มีระบุ Dependencies ให้กับ `useEffec()` ด้วย ทำให้มันเมื่อ component mount ครั้งแรกเท่านั้น พอมีการเปลี่ยน paramemter ที่ URL หน้านั้นไม่ได้ถือว่าโหลดซ้ำแค่เปลี่ยน Parameter เฉยๆ พอ `useEffect()` ไม่รู้ว่า `requestID` เปลี่ยนแล้วก็ไม่มีการรันซ้ำ | ลบทุกอย่างที่เกี่ยวกับ `ignore` ออก และเพ่ิม dependencies ให้กับ `useEffect((), [reloadKey, requestID])` ทำให้ `useEffect()` สามารถรันใหม่ได้เมื่อ parameter เปลี่ยนแล้ว `requestID` ใน Dependencies ก็จะบอกให้ `useEffect()` ทำงานใหม่ |
| 5 | กด "ลบ" แล้วการ์ดหาย แต่ตัวเลขในแผงสรุปไม่ลด | `DashboardPage.jsx : 66` | บัคนี้ไม่รู้เข้าใจถูกมั้ย เวลากดลบ สามารถลบได้ปกติโดยที่ตัวเลขใน `SummaryPanel` ก็ลดตามไปด้วย แต่มีการเปรียบเทียบผิดใน `requests.filter` โดยเปรียบเทียบเป็น `completed: requests.filter((request) => request.status === "in-progress").length,` ทำให้มันทำงานไม่ปกติ แสดงค่า 'กำลังดำเนินการ' ในช่อง 'เสร็จสื้น' แทน | เปลี่ยนเป็น `completed: requests.filter((request) => request.status === "completed").length,` |
| 6 | กด "ลบ" แล้วหน้าพัง/ว่างเปล่า | `DashboardPage.jsx : 64` | ไม่มีการประกาศ await ก่อนที่ promise (ณ ที่นี้คือ `deleteRequest(requestID)` โดยที่มันทำงานโดยการลบ request นั้นๆ ด้วย `requestID` และคืนค่าที่เหลือเป็น Array) จะ resolved ทำให้ Promise นี้มีการคืนค่าทันทีแบบไม่ใช่ array และเหตุผลที่ทำให้ระบบพังหรือหน้าขาวเพราะ `.map()` ต้องทำงานกับค่าที่เป็น array เท่านั้น เมื่อไม่มีการดัก error ก็พังเลย | เพิ่ม `await deleteRequest(requestID)` เพื่อรอให้มันสามารถคืนค่าเป็น array ให้ได้ก่อน |
